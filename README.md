# 코골이체커

> 수면무호흡 환자의 약 85%가 진료를 받지 않는다. 정보는 있지만, 내 코골이가 병원에 가볼 만한 상태인지 스스로 판단하지 못해서 밴드·스프레이·각방으로 버틴다.

질문 9개에 답하면 내 코골이가 혼자 대처해도 되는지, 검사가 필요한지 판정(신호 약함 / 상담 권유 / 검사 권유)을 바로 받고, 검사가 필요하면 근처 수면클리닉의 원 페이지로 넘어가는 서비스다. 첫 질문에서 "내 코골이"와 "함께 자는 사람의 코골이" 중 하나를 고르고, 경로에 맞는 말로 묻는다. 함께 자는 사람의 코골이라면 리포트를 그 사람에게 링크로 보낼 수 있다.

- **서비스 링크:** https://snore-checker-lab.vercel.app
- **제출 당시 버전:** https://snore-check.vercel.app ([원본 레포](https://github.com/fe1220/snore-checker)). 이 레포는 제출 뒤 메타 광고 1차 결과를 반영해 문제 정의와 화면을 다시 잡은 실험용 레포다.
- **대상:** 자기 코골이가 걱정인 당사자, 또는 함께 자는 사람의 코골이가 걱정인 사람. 누구에게 말을 걸지는 [H1](docs/validation.md#h1-당사자에게-말을-거는-게-병원까지-더-잘-이어진다)으로 검증한다
- **북극성 지표:** 검사 권유 판정을 본 사람 중 병원에 연결된 비율(병원 외부 링크 클릭 또는 전화 걸기)

> **제출 이후 변경:** 크롤러가 매주 월요일 03:00(KST)에 GitHub Actions로 병원 데이터를 다시 수집해 `frontend/src/data/*.json`을 자동 커밋한다. 그래서 제출 뒤에도 이 저장소와 배포된 사이트의 병원 목록이 바뀔 수 있다.

## 문제 정의 요약

- **출발점:** 작성자가 어머니에게 네 가지(병일 수 있다, 치료된다, 방치하면 위험하다, 어디서 어떻게 검사받는다)를 알려주자 어머니가 움직였고, 아버지는 진단과 양압기 치료까지 갔다. 병원에 갈 일이라는 판단이 서자 움직였다.
- **왜 문제인가:** [사실] 성인 남성 약 4%가 수면무호흡이고 검사와 양압기에 건강보험이 된다. [추정] 그런데 환자의 약 15%만 진료받는다. 남은 병목은 병원에 갈 일인지 판단하는 단계다.
- **무엇이 바뀌었나:** 처음엔 "괴로운 건 배우자, 가야 하는 건 당사자"로 배우자에게 말을 걸었다. 1차 메타 광고는 배우자 시점 소재로도 남성에게 87%가 나갔고, 일반 키워드 커뮤니티 글은 당사자 글이 72%였다. 정보는 이미 있었다(답변의 64%가 수면무호흡을 언급). 그래서 문제를 "스스로 판단하지 못한다"로 다시 잡고, 누구에게 말을 걸지는 실험으로 정한다([문제 정의 전략](docs/problem-framing.md#고쳐-온-과정)).
- **빈자리:** 국내외 서비스 46건을 직접 확인했다. 배우자에게 말을 거는 곳은 있지만 대부분 자사 상담이나 제품으로 끝나고, 옆에서 본 것으로 체크해 중립 병원 목록까지 잇는 곳은 없었다([벤치마크](docs/research/benchmark.md)). 국내 수면클리닉 95곳 홈페이지에서는 읽을 수 있었던 81곳 중 배우자에게 직접 말을 거는 곳이 0곳이었다([전수 조사](docs/research/clinic-survey.md)).

## 로컬 실행

Node.js 24+, pnpm이 필요하다 (`corepack enable pnpm`).

```bash
make setup   # 의존성 설치, frontend/.env.local 생성
make dev     # http://localhost:3000
make crawl   # 크롤링 → frontend/src/data/hospitals.json
make meta-report  # 메타 광고 + GA4 숫자 → docs/meta-ads/results/<날짜>.md (설정: reporting/.env.local)
make gate    # 타입체크·린트·포맷·테스트·빌드, 크롤러 테스트, 접근성 측정
```

DB와 백엔드 서버 없이 동작한다. 체크 응답은 저장하거나 보내지 않고 리포트 주소의 `#` 뒤에만 담는다. 근거는 [tech-stack](docs/tech-stack.md).
