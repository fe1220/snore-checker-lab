# 화면 설계

상태: 승인

> **목적:** 광고 유입부터 병원 원 페이지까지 다섯 화면(S1~S4, S3')의 정보 위계, 흐름, 상태별 동작, 40~60대 접근성 기준을 정한다.
>
> **결론:** 랜딩은 약속("내 코골이, 병원에 가볼 만할까요?")과 첫 질문("누구의 코골이가 궁금하세요?")만 두고, 답에 따라 당사자·배우자 경로로 나눈다. 두 경로는 같은 질문 9개와 같은 판정 기준을 쓰고 표현만 다르다. 화면마다 주요 행동은 하나다. 리포트는 판정 → 신호 → 위험 → 이득 → 방법 → 출처 순이다. 병원 744곳은 "전국"으로 시작하고 위치는 "가까운 순"을 누를 때만 묻는다. 글자 16px·터치 48px·대비 7:1 이상이 기준이다.

[문제 정의](problem-definition.md)와 [솔루션 방향](solution-direction.md)을 화면으로 옮기기 전에 정보 위계, 화면 흐름, 상태별 동작을 정한다. 시각 규칙은 [DESIGN.md](../DESIGN.md)를 따른다.

## 범위

광고로 들어온 사람이 누구의 코골이인지 고르고, 질문에 답하고, 리포트를 보고, 근처 수면클리닉의 원 페이지로 넘어가기까지다. 경로는 둘이다. 당사자 경로는 "내 코골이", 배우자 경로는 "함께 자는 사람의 코골이"를 고른 사람이다([H1](validation.md#h1-당사자에게-말을-거는-게-병원까지-더-잘-이어진다)).

| # | 화면 | 주요 행동 (화면당 1개) | 지금 상태 |
|---|---|---|---|
| S1 | 랜딩 + 첫 질문 | 누구의 코골이인지 고르기 | 다시 짠다(작업 09). 실험용 카피별 랜딩 3개(`/c/heal`·`/c/disease`·`/c/sleep`)는 쓰이지 않아 지운다 |
| S2 | 질문 9개 (경로별 표현) | 답 고르기 | 배포됨. 경로별 표현을 더한다(작업 09) |
| S3 | 수면 진단 리포트 | 근처 수면클리닉 찾기 | 배포됨. 경로별 차이를 더한다(작업 09) |
| S4 | 근처 수면클리닉 | 병원 정보 보기 (외부 링크) | 배포됨(`/clinics`). 병원 744곳, 학회 목록 배지 |
| S3' | 공유받은 리포트 | 근처 수면클리닉 찾기 | 배포됨 |

## 흐름

```
메타 광고 (utm_content=소재)
  → S1 랜딩: "누구의 코골이가 궁금하세요?"
       ├ 내 코골이 ──────────── 당사자 경로
       └ 함께 자는 사람의 코골이 ── 배우자 경로
  → S2 질문 9개 (한 화면에 한 질문, 답하면 다음으로. 경로별 표현)
  → S3 리포트 ──── (배우자 경로만) 리포트 보내기 → 카톡 등 공유창 → S3' 공유받은 리포트
  → S4 근처 수면클리닉
  → 병원 원 페이지 (새 탭, 외부 링크)
```

## S1 랜딩 + 첫 질문

처음부터 다시 짠다. 서비스의 핵심 역할은 판단이라, 첫 화면에는 "병원에 가볼 만한지 알려준다"는 약속과 시작 행동(첫 질문)만 둔다. 설문형 서비스(삼쩜삼, 토스 신용점수, Noom)도 결과 약속과 첫 질문을 먼저 두고 설명은 뒤로 미룬다. 결정 과정은 [기획 로그](planning-log.md#2026-10-06-화면-설계-당사자배우자-경로-나누기)에 있다.

| 위계 | 내용 | 처리 |
|---|---|---|
| 0 | 코골이체커 + 작은 달 그림(광고 소재와 이어지게) | 한 줄, `text-base text-muted-foreground` |
| 1 | 약속: "내 코골이,\n병원에 가볼 만할까요?" | `text-3xl font-extrabold` |
| 2 | 보조: "질문 9개에 답하면 바로 알려드려요" | `text-lg font-semibold text-primary` |
| 3 | 첫 질문: "누구의 코골이가 궁금하세요?" | `text-xl font-semibold` |
| 4 | 선택 카드 두 장 | `bg-card` 카드, 최소 높이 88px, 카드 전체가 누르는 영역 |
| 5 | 신뢰 한 줄: "무료 · 답은 어디에도 저장되지 않아요 / 의사의 진단을 대신하지 않아요 · 개인정보처리방침" | 화면 아래, `text-base text-muted-foreground` |

**선택 카드**

| 카드 | 제목 | 설명 | 경로 |
|---|---|---|---|
| 1 | 내 코골이 | 코 곤다는 말을 듣거나, 자고 나도 피곤해요 | 당사자 |
| 2 | 함께 자는 사람의 코골이 | 옆에서 코 고는 소리나 숨 멈춤을 봐요 | 배우자 |

- 카드 설명은 "이게 내 얘기다"를 알아보게 하는 문장이다.
- 카드 안에 다른 버튼이나 링크를 두지 않는다. 누르면 고른 카드가 노랑 테두리로 잠깐 바뀐 뒤 질문 1로 넘어간다(S2 답 버튼과 같은 200ms).
- 노랑으로 채운 주요 버튼과 하단 고정 바를 두지 않는다. 이 화면의 할 일은 "고르기" 하나이고, 두 카드는 같은 위계의 선택지다.
- 기존 안심 포인트 목록과 큰 달·별 그림은 뺐다. 약속 문장과 신뢰 한 줄이 그 역할을 한다.
- "3분 무료진단"은 랜딩에서 빠진다. 2차 광고 소재는 이 약속에 맞춰 새로 만든다.

## S2 질문

- 한 화면에 한 질문, 답 세 개(네 / 아니요 / 잘 모르겠어요). 고르면 바로 다음으로 넘어간다.
- 위에 진행 막대와 "n / 9 · 안내", 뒤로 가기. 질문 1에서 뒤로 가면 랜딩(첫 질문)으로 간다. 첫 질문은 경로를 고르는 질문이라 9개 진행에 넣지 않는다.
- 두 경로는 같은 9개 항목과 같은 판정 기준을 쓴다. 표현만 다르다. 항목이나 기준이 다르면 결과 차이가 사람 때문인지 질문 때문인지 가를 수 없다(H1).
- 질문은 STOP-Bang 구조를 참고한 자체 질문이다. 체중 질문은 체형 평가처럼 들리지 않게 "최근 몇 년 사이 체중이 늘었어요"로 묻는다.

| 경로 | 안내 |
|---|---|
| 당사자 | 듣거나 느낀 대로 답해 주세요 |
| 배우자 | 함께 자는 사람을 옆에서 본 대로 답해 주세요 |

| # | 당사자 경로 | 배우자 경로 |
|---|---|---|
| 1 | 일주일에 3번 이상 코를 곤다는 말을 들어요 | 일주일에 3번 이상 코를 골아요 |
| 2 | 코 고는 소리가 문을 닫아도 들릴 만큼 크다는 말을 들어요 | 코 고는 소리가 문을 닫아도 들릴 만큼 커요 |
| 3 | 자다가 숨이 멈춘다는 말을 들은 적 있어요 | 자다가 숨이 멈추는 걸 본 적 있어요 |
| 4 | 자다가 컥 하거나 숨이 막혀 깬 적 있어요 | 자다가 컥 하거나 헐떡이며 숨을 몰아쉬어요 |
| 5 | 운전하다 졸은 적 있어요 | 운전하다 조는 걸 본 적 있어요 |
| 6 | 앉아 있거나 TV를 보면 금방 졸아요 | 앉아 있거나 TV를 볼 때 금방 조는 걸 자주 봐요 |
| 7 | 고혈압이 있어요 | 코 고는 사람이 고혈압이 있어요 |
| 8 | 50세 이상이에요 | 코 고는 사람이 50세 이상이에요 |
| 9 | 최근 몇 년 사이 체중이 늘었어요 | 코 고는 사람이 최근 몇 년 사이 체중이 늘었어요 |

- 배우자 경로는 주어 없이 쓰고, 답하는 사람 본인 얘기로 헷갈릴 수 있는 사람 정보(7~9)만 "코 고는 사람이"를 붙인다. 코 고는 사람이 남편이 아닐 수 있다.
- 6번 배우자 경로에 "자주"를 붙인다. 낮에 한 번 조는 건 누구나 있다.

## S3 수면 진단 리포트

레퍼런스(NHS 케어카드, 애플워치 수면무호흡 알림, 국가건강검진 결과통보서, 23andMe, Oura·Withings, ResMed 결과 페이지)에서 공통 원칙을 가져왔다: 판정과 할 일을 한 문장으로 맨 위에, 단계는 3개로 색·문구 고정, 숫자는 기준 대비 막대로, 근거는 펼쳐서, 강조 행동은 하나.

**정보 위계 (읽는 사람의 질문 순서)**

| 순서 | 읽는 사람의 질문 | 영역 | 처리 |
|---|---|---|---|
| 0 | 이게 뭐지? | 문서 머리말: 수면 진단 리포트 · 옆에서 본 9가지 질문. 공유받은 리포트에서는 "함께 자는 사람이 옆에서 보고 답한 리포트예요"로 바꿔 누가 답했는지 밝힌다. 날짜는 두지 않는다(해시에 날짜가 없어 공유받은 사람에게 연 날이 찍힌다) | 얇은 줄, xs |
| 1 | 그래서 어떻다는 거야? | 판정: 3칸 단계 막대(신호 약함 / 상담 권유 / 검사 권유. 세 색을 옅게 이어 깔고 현재 단계만 진하게, 위에 ▼, 라벨 굵게) + 판정 문장 + 한 줄 이유 + 수면무호흡증 정의 | 카드 없이 전체 폭. 공유 미리보기 이미지와 같은 막대. 제목 2xl |
| 2 | 왜 그렇게 판단해? | 옆에서 본 신호 (9개 중 n개), 주요 신호 표시 | 카드 |
| 3 | 그냥 두면? | 치료하지 않으면: 졸음운전 사고 2.4배, 심혈관 질환(중증) 2.9배 | 카드, 기준(일반인 1) 대비 막대 + 각주. 신호 약함에서는 숨긴다(신호가 적은 사람에게 위험 수치는 겁주기로 읽힌다) |
| 2-1 | 자는 동안 무슨 일이? | 자는 동안 이런 일이 생겨요: 숨이 멈출 때마다 깬다, 중등도면 한 시간에 15번 이상 | 카드, 한 문단에 횟수 문장만 굵게. 신호 약함에서는 숨긴다 |
| 4 | 고치면? | 치료하면: "잠이 달라지면 삶이 달라져요" + 본인의 영역별 한 줄 이득(잠·머리·기분·운전·관계·혈압·화장실·성기능). 수치는 운전(사고 위험 약 70% 감소)에만. 아래에 보조로 "함께 자는 사람도 더 깊이 자요" | 카드 하나. 본인 이득이 주, 함께 자는 사람은 구분선 아래 보조. 영역 이름 + 내용 2열. 신호 약함에서는 숨긴다 |
| 5 | 뭘 하면 돼? | 검사는 이렇게 받아요: 3단계, 주말 검사, 본인부담 약 12~14만 원 | 카드, 번호 단계 |
| 6 | 믿어도 돼? | 판단 기준 / 출처 (접힘), 진단 아님 한 줄 | Accordion, sm·xs |
| CTA | | 하단 고정: 근처 수면클리닉 찾기 (주요) / 리포트 보내기 (보조, ghost) | |

**판정 문구**

| 단계 | 단계 이름 | 제목 | 막대 색 |
|---|---|---|---|
| 강한 신호 1개 이상 | 검사 권유 | 수면무호흡증 신호가 보여요. 수면검사를 권해요 | danger(빨강) |
| 그 외 신호 3개 이상 | 상담 권유 | 수면무호흡증 신호가 여러 개예요. 상담을 권해요 | warning(코랄) |
| 그 외 | 신호 약함 | 지금은 걱정 신호가 적어요 | success(초록) |

- 신호 약함이면서 주요 신호 문항(숨 멈춤·헐떡임·운전 중 졸음) 중 "잘 모르겠어요"가 하나라도 있으면 제목을 "아직 판단하기 일러요", 설명을 "숨 멈춤은 자는 동안 지켜봐야 알 수 있어요. 며칠 밤 옆에서 본 뒤 다시 해 보세요."로 바꾼다. 단계 막대와 GA `level`은 신호 약함 그대로다. 관찰하지 못한 사람에게 "신호가 적다"는 잘못된 안심을 주지 않으려는 것이다([QA 반영](work/07-qa-fixes/spec.md)).

**수치 원칙** (근거 검증 결과)
- 막대는 위험 쪽에만 쓴다. 심혈관 2.9배는 "남성 대상 관찰 연구"를 출처에 명시하고, 치료 쪽에는 심혈관을 넣지 않는다(SAVE 시험에서 치료 효과 미확인).
- 배우자 이득은 환산값(+62분) 대신 측정값(수면 효율 74% → 87%)을 쓰고 소규모 연구임을 밝힌다.
- 본인 이득은 "숨 멈춤 → 잠이 깨짐 → 삶 전반"으로 연결해 영역별로 넓게 보여준다. 치료 효과 메타분석이 있는 것만 넣는다: 사고 위험(Tregear 2010), 기분(Povitz 2014), 야간뇨(Wang 2015), 성기능(Clin Respir J 2021 메타분석, "나아질 수 있어요"로 약하게).
- 기억력(치료 효과가 주의력에 한정)과 체중·혈당은 치료 이득으로 쓰지 않는다.

**경로별 차이**

판정 기준, 판정 문구, 정보 위계(판정 → 신호 → 위험 → 이득 → 방법 → 출처)는 두 경로가 같다. 아래만 다르다.

| 영역 | 당사자 경로 | 배우자 경로 |
|---|---|---|
| 머리말 | 수면 진단 리포트 · 내가 답한 9가지 질문 | 수면 진단 리포트 · 옆에서 본 9가지 질문 |
| 아직 판단하기 일러요 (설명) | 숨 멈춤은 자는 동안 일어나 스스로 알기 어려워요. 며칠 밤 녹음해 보거나 함께 자는 사람에게 물어본 뒤 다시 해 보세요. | 숨 멈춤은 자는 동안 지켜봐야 알 수 있어요. 며칠 밤 옆에서 본 뒤 다시 해 보세요. (지금 그대로) |
| 보조 버튼 | 없음. 주요 버튼(근처 수면클리닉 찾기) 하나만 둔다 | 리포트 보내기 (지금 그대로) |

- 당사자는 본인이 병원에 갈 사람이라 공유가 다음 행동이 아니다. 공유받은 리포트가 두 종류가 되면 받는 화면 문구와 측정이 두 갈래로 는다.
- 경로는 리포트 주소 해시에 담지 않고 쿼리(`?for=self`)로 넘긴다. 응답이 아니라 화면 표현을 고르는 값이다. 공유 링크는 배우자 경로에서만 만들므로 S3'는 지금처럼 배우자가 답한 리포트다.

**신호 약함의 다음 행동**

신호 약함은 병원을 권하지 않는다. 이 서비스의 목적은 병원에 보내는 게 아니라 맞는 대처를 고르게 하는 것이다([문제 정의 전략](problem-framing.md#이-프로젝트에-적용)). 설명을 "그래도 걱정되면 언제든 상담받아 보세요"에서 아래로 바꾼다.

> 지금은 옆으로 자기, 체중과 술 줄이기 같은 생활습관부터 해 보세요. 숨이 멈추거나 낮에 자꾸 졸리면 다시 진단해 보세요.

**공유받은 리포트 (S3')**
- 같은 리포트에 판정 위로 한 줄 "요즘 낮에 졸리고 피곤했다면, 수면무호흡증 때문일 수 있어요"를 붙인다(신호 약함일 때는 뺀다). 리포트 보내기 버튼은 없다.
- 응답은 주소 해시에 버전과 함께 인코딩한다(`tech-stack.md`). 지금 형식은 "네"와 "잘 모르겠어요"를 따로 담는 `#v2-<네>-<모름>`이다. "네"만 담던 `#v1-<네>` 링크도 이미 퍼져 있어 계속 연다(모름은 없는 것으로 본다). 해시는 서버·분석 도구로 전송되지 않는다. 그래서 리포트는 클라이언트에서 그린다.
- 카톡 미리보기는 OG 이미지 하나("옆에서 본 코골이, 병원에 가볼 만할까요?")로 고정한다.

## S4 근처 수면클리닉

크롤링 필수 요건이 걸린 화면이다. 처음엔 레즈메드 병원찾기(337곳)만으로 냈고, 이후 심평원 공공 데이터의 수면다원검사 실시기관으로 744곳까지 넓히고 대한수면연구학회 목록 병원 73곳에 "수면학회 등록" 배지를 달았다. 학회 배지는 병원을 잘못 맞추지 않도록 전화번호와 이름·주소를 함께 맞춘 경우에만 붙인다([병원 데이터 보강](work/03-clinic-data/spec.md)).

| 위계 | 내용 |
|---|---|
| 1 | 제목 "근처 수면클리닉" + 출처와 마지막 수집 시각 (예: 레즈메드 병원찾기 · 건강보험심사평가원 2026년 6월 · 10월 3일 수집) |
| 2 | 보기 방식 두 버튼을 한 줄에: 지역 선택 ("전국 · 337곳", 하단 Sheet) / 가까운 순 |
| 3 | 병원 카드 목록: 병원명, (내 주변일 때) 거리, 주소, 전화하기 / 병원 정보 보기(외부 링크, 새 탭) |

**보기 방식**

| 방식 | 목록 | 카드 |
|---|---|---|
| 지역 (기본 "전국") | 고른 시·도, 수면학회 등록 병원 먼저 그다음 주소 가나다순 | 거리 없음 |
| 내 주변 | 전국, 가까운 순 | 거리 표시 ("2.3km") |

- 처음에는 위치 권한을 묻지 않고 "전국"으로 시작한다. 디지털 친숙도가 낮은 대상이라 들어오자마자 권한 창을 띄우지 않는다.
- 권한은 "가까운 순"을 눌렀을 때만 요청한다. 이유를 알고 누른 뒤라 당황하지 않는다(네이버 지도, 굿닥, 똑닥과 같은 방식).
- 지역을 고르면 지역 방식으로, 내 주변을 누르면 내 주변 방식으로 바뀐다. 둘을 조합하지 않는다. 지금 방식의 버튼에 선택 상태(`primary` 글자·테두리)를 준다.
- 지역 Sheet에는 병원이 있는 시·도만 건수와 함께 보여준다("서울 81").
- 목록은 나누지 않고 전부 보여준다. "더 보기"나 페이지 번호를 두지 않는다. 스크롤이 가장 익숙한 동작이고, 필요한 병원은 지역 선택과 거리 순으로 위에 오게 한다.
- "전국" 보기에서는 지역이 바뀌는 자리에 시·도 소제목("서울 81곳")을 둔다. 337곳을 스크롤하는 동안 지금 어느 지역인지 알 수 있어야 한다.
- 위치는 브라우저 안에서 거리 계산에만 쓰고 저장·전송하지 않는다.

**카드**

- 카드 전체를 링크로 만들지 않는다. 카드 안에 전화하기와 병원 정보 보기 버튼 두 개를 둔다.
- 주소는 모든 카드에서 네이버 지도 링크다. 앞에 위치 핀, 뒤에 외부 링크 아이콘을 붙이고 주소에 밑줄을 긋는다. 밑줄만으로는 누를 수 있는지 알기 어렵다. "병원 정보 보기"도 지도로 가는 병원은 링크가 겹치지만, 카드마다 주소 모양이 달라지는 것보다 낫다고 정했다.
- 병원 홈페이지는 크롤링할 때마다 접속을 확인하고, 열리지 않으면 지워서 지도로 보낸다.
- 두 버튼 모두 `outline`이다. 주요 행동인 병원 정보 보기만 `primary` 글자·테두리로 강조한다. 카드마다 노랑으로 채운 버튼을 두면 화면에 주요 버튼이 수십 개가 된다.
- 이 화면에는 하단 고정 바를 두지 않는다. 화면 전체에 하나뿐인 행동이 없다.

**뺀 것**

- 주말 검사 안내: 리포트의 "검사는 이렇게 받아요"와 겹치고, 어느 병원이 되는지 데이터가 없어 숙제만 준다.
- 병원 광고(상단 노출 + "광고" 표시): 수익 모델에 있지만 MVP에는 자리를 만들지 않는다.

## 접근성 (40~60대 기준)

사용자는 40~60대이고 메타 광고의 인앱 브라우저로 들어온다. 현재 화면을 재보니 리포트 핵심 문장이 14px, 면책 문구가 12px, 뒤로 가기가 36px이었다. 기준 출처와 측정값은 [accessibility](research/accessibility.md)에 있다.

**전제**

- 아이폰은 시스템 글자 크기를 웹에 반영하지 않고, 안드로이드는 글자만 키우고 여백은 그대로 둔다. 사용자가 직접 키우기를 기대할 수 없어 기본값을 크게 잡는다.
- "큰 글씨 모드"를 따로 만들지 않는다. 토스는 별도 시니어 화면을 시도했다가 철회했고, 케이뱅크·카카오뱅크는 큰 글씨·큰 버튼·쉬운 용어로 갔다. 화면이 하나여야 광고에서 본 것과 같은 화면이 나온다.
- 다크 테마는 유지한다. 밝은 배경이 고령자를 포함해 대부분에게 읽기 유리하다는 연구가 있지만(Piepenbrock 2013), 광고 소재와 팔레트가 이어져야 한다. 대신 글자 대비를 7:1로 올리고 글자를 키워 보완한다.

**기준**

| 항목 | 이전 | 기준 | 근거 |
|---|---|---|---|
| 읽는 글자 최소 크기 | 12~14px 허용 | 16px. 본문은 18px | 서울디지털재단 고령층 친화 표준(14pt, 기사 기준). 18px은 자체 제안값 |
| 글자 대비 | 4.5:1 | 7:1 | WCAG 1.4.6 |
| 테두리·아이콘 대비 | 없음 | 3:1 | WCAG 1.4.11 |
| 터치 영역 | 44px | 48px. 주요 버튼은 56px | Material 48dp. 56px은 자체 제안값 |
| 터치 영역 사이 | 없음 | 8px 이상 | Material |
| 줄 간격 | 없음 | 1.5 이상 | WCAG 1.4.12 |
| 확대 | 없음 | 글자 200%와 폭 320px에서 잘림·겹침·가로 스크롤 없음 | WCAG 1.4.4, 1.4.10 |
| 글자가 든 요소의 높이 | 고정 | 최소 높이만 정한다 | 위 확대 기준의 수단 |
| 움직임 | 1곳만 대응 | "동작 줄이기" 설정이면 전환 효과를 끈다 | WCAG 2.3.3 |
| 색 | - | 판정 단계와 주요 신호는 색과 글자를 함께 쓴다 | WCAG 1.4.1 |

**화면별로 바뀌는 것**

| 화면 | 바뀌는 것 |
|---|---|
| S1 | 선택 카드 최소 높이 88px. 글자 200%에서 카드 두 장이 첫 화면에 들어오는지 확인한다 |
| S2 | 뒤로 가기 36px → 48px. 안내 문구 14px → 16px. 선택지는 글자가 커져도 넘치지 않게 최소 높이로 |
| S3 | 핵심 한 줄, 수면무호흡증 설명, 단계 설명 14px → 18px. 머리말, 막대 라벨, 주요 신호 칩, 각주, 면책 문구 12~14px → 16px. 막대 라벨 열은 고정 폭을 풀어 줄바꿈되게 |
| S4 | 주소·거리·건수·위치 오류 안내 14px → 16px. 버튼 44px → 48px. 지역 이름이 잘리지 않게 |
| 공통 | 보조 글자색·경고색을 밝게, 테두리를 진하게 조정(토큰). 전환 효과에 동작 줄이기 대응 |

- 리포트가 길어진다. 위계(판정 → 신호 → 위험 → 이득 → 방법 → 출처)는 그대로 두고, 크기 차이가 줄어든 만큼 보조 정보는 색(`muted-foreground`)과 굵기로 구분한다.
- 위 표의 "xs", "sm" 표기는 이 섹션 기준으로 대체한다. 16px 미만 글자는 쓰지 않는다.

**검증**

- 전 화면의 글자 크기, 터치 영역, 대비를 브라우저에서 재는 스크립트를 `make gate`에 넣는다.
- 폭 320·375px × 글자 100·130·200% 스크린샷을 [검증](work/02-a11y-copy/verification.md)에 남긴다.

## 측정

- 첫 질문에서 카드를 고르면 `check_start`를 보내고, 경로를 GA 사용자 속성 `respondent_role`(`self` / `partner`)로 저장한다. 판정 단계 속성(`check_level`)과 같은 방식이다([작업 08](work/08-measurement/spec.md)).
- 그래서 "랜딩 사용자 중 첫 질문 응답률"(목표 50% 이상)이 곧 체크 시작률이다. 지금까지는 질문 1의 답에서 `check_start`가 찍혀 랜딩 이탈과 질문 이탈을 나누기 어려웠다.
- 경로는 응답자 역할이라 GA로 보낼 수 있다. 증상 답은 지금처럼 보내지 않는다(CLAUDE.md). 메타 픽셀에는 보내지 않는다.

## 화면 간 일관성

- 판정 단계 이름(신호 약함 / 상담 권유 / 검사 권유)은 단계 막대, 제목, 판단 기준에서 같은 말을 쓴다.
- 주요 버튼은 모두 하단 고정 바, 전체 폭, 최소 높이 56px(`min-h-14`). (S1과 S4는 고정 바가 없다. S1은 같은 위계의 선택 카드 두 장이다)
- 코 고는 사람을 부르는 말: 배우자 경로 질문은 주어를 빼고, 필요한 곳만 "코 고는 사람". 공유받은 리포트는 지금처럼 "당신". `DESIGN.md` 용어 표의 "남편"을 이에 맞춰 고친다.
- 외부로 나가는 링크에는 모두 외부 링크 아이콘을 붙인다. 리포트의 "근처 수면클리닉 찾기"는 이제 서비스 안의 S4로 가므로 아이콘을 뺀다.

## 모바일 / 데스크탑

375px 기준으로 설계하고 320px에서도 가로 스크롤이 없어야 한다. 데스크탑은 `max-w-screen-md` 가운데 정렬로 늘리기만 하고 배치를 바꾸지 않는다. 유입이 모바일 광고라서다.

## 리스크

| 리스크 | 대응 |
|---|---|
| 랜딩에 노랑 주요 버튼이 없어 광고에서 막 들어온 사람이 누를 곳을 못 찾는다 | 첫 질문을 화면 가운데에 크게 두고 카드에 오른쪽 화살표를 붙인다. 첫 질문 응답률(목표 50%)로 확인한다 |
| 혼자 자는 당사자는 숨 멈춤 같은 질문에 "잘 모르겠어요"가 많다 | "아직 판단하기 일러요"에서 녹음이나 함께 자는 사람에게 물어보기를 안내한다 |
| 리포트의 위험 수치가 공포 마케팅처럼 읽힌다 | 기준 대비 막대와 출처, 연구 성격을 함께 보여주고 경고색은 막대 하나에만 쓴다 |
| 해시 기반 리포트라 서버 렌더링이 안 되고 첫 화면이 늦다 | 리포트 모양 Skeleton으로 빈 화면을 막는다 |
| 지역 필터만으로는 "가까운 곳"을 찾기 어렵다 | "가까운 순"을 함께 둔다. 시·군·구 선택은 확장 단계로 둔다 |
| 메타 광고의 인앱 브라우저에서 위치 요청이 막힐 수 있다 | 실패 안내를 보여주고 지역 선택으로 계속 쓸 수 있게 한다 |
| 다크 테마가 노안 사용자에게 읽기 불리할 수 있다 | 글자 대비 7:1, 본문 18px로 보완한다. 밝은 테마는 광고 소재를 바꿀 때 함께 검토한다 |
