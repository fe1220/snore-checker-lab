# 스펙: 랜딩 재설계와 당사자·배우자 경로

상태: 승인

> **목적:** 랜딩 이탈(랜딩 사용자 중 27%만 체크로 넘어감)을 줄이고, 첫 질문으로 당사자·배우자 경로를 나눠 [H1](../../validation.md#h1-당사자에게-말을-거는-게-병원까지-더-잘-이어진다)을 잴 수 있게 한다.
>
> **결론:** 랜딩을 약속 + 첫 질문(카드 두 장)으로 다시 짜고, 고른 경로에 따라 질문·리포트 표현을 바꾼다. 판정 기준은 그대로다. 경로는 GA 사용자 속성 `respondent_role`로 저장한다.

화면 설계: [ux-spec](../../ux-spec.md) S1, S2, S3, 측정. 결정 근거: [기획 로그](../../planning-log.md#2026-10-06-화면-설계-당사자배우자-경로-나누기).

## 요구사항

### 1. 랜딩 (S1)

- `/`를 ux-spec S1 구조로 다시 만든다: 브랜드 + 작은 달 그림, 약속("내 코골이,\n병원에 가볼 만할까요?"), 보조("질문 9개에 답하면 바로 알려드려요"), 첫 질문("누구의 코골이가 궁금하세요?"), 선택 카드 두 장, 신뢰 한 줄(무료 · 답은 어디에도 저장되지 않아요 / 의사의 진단을 대신하지 않아요 · 개인정보처리방침 링크).
- 카드: "내 코골이 / 코 곤다는 말을 듣거나, 자고 나도 피곤해요"(당사자), "함께 자는 사람의 코골이 / 옆에서 코 고는 소리나 숨 멈춤을 봐요"(배우자). 카드 전체가 누르는 영역이고 안에 다른 링크가 없다. 최소 높이 88px.
- 고르면 카드가 200ms 선택 상태로 바뀐 뒤 `/check?for=self` 또는 `/check?for=partner`로 간다. 고르는 순간 `check_start`를 보내고 `respondent_role`(`self` / `partner`)을 사용자 속성으로 저장한다.
- 노랑 주요 버튼과 하단 고정 바를 두지 않는다.
- 실험용 카피별 랜딩 `/c/heal`·`/c/disease`·`/c/sleep`과 `HEADLINES`를 지운다(쓰이지 않는 경로).

### 2. 질문 (S2)

- `for` 값이 `self` 또는 `partner`가 아니면(없거나 옛 링크 `?from=heal` 포함) `/`로 보낸다.
- 질문 9개의 항목·순서·판정 기준(`judge()`)은 그대로다. 경로별 문구와 안내는 ux-spec S2 표를 따른다. 문구는 `lib`에 경로별로 한 번만 정의한다.
- 안내: 당사자 "듣거나 느낀 대로 답해 주세요", 배우자 "함께 자는 사람을 옆에서 본 대로 답해 주세요".
- 질문 1에서 뒤로 가면 랜딩으로 간다.
- `check_start`는 랜딩으로 옮겼으므로 질문 1의 답에서는 보내지 않는다.
- 리포트로 갈 때 `/r?for=<경로>#<해시>`로 간다. 해시 형식(v2)은 그대로다.

### 3. 리포트 (S3)

- `for=self`면: 머리말 "수면 진단 리포트 · 내가 답한 9가지 질문", 신호 카드 제목 "내가 답한 신호", "아직 판단하기 일러요" 설명 "숨 멈춤은 자는 동안 일어나 스스로 알기 어려워요. 며칠 밤 녹음해 보거나 함께 자는 사람에게 물어본 뒤 다시 해 보세요.", "리포트 보내기" 버튼 없음.
- `for=partner` 또는 값이 없으면: 지금 그대로(옛 리포트 링크는 배우자 기준으로 연다).
- 신호 약함 설명(두 경로 공통): "지금은 옆으로 자기, 체중과 술 줄이기 같은 생활습관부터 해 보세요. 숨이 멈추거나 낮에 자꾸 졸리면 다시 진단해 보세요."
- 공유 링크는 배우자 경로에서만 만든다. 형식(`/r?shared=1#...`)은 그대로다.
- 리포트의 판정 문구, 위험·이득·방법 카드는 그대로다. 질문 문구를 보여주는 곳(판단 기준, 신호 목록)은 경로별 문구를 쓴다.

### 4. 측정

- `respondent_role` 사용자 속성을 저장한다(작업 08의 `check_level`·`report_source`와 같은 방식, `components/analytics/track.ts`).
- 리포트(`make meta-report`)의 판정 단계별 표와 같은 방식으로 경로별 사람 수 퍼널(체크 시작 → 체크 완료 → 병원 목록 진입 → 병원 연결)을 더한다. 맞춤 측정기준이 없으면 "아직 없다"로 쓴다.
- GA 관리자에서 `respondent_role`을 사용자 범위 맞춤 측정기준으로 등록한다(사용자 수동 작업).

### 5. 문서

- `DESIGN.md` 용어 표: 코 고는 사람을 "남편"에서 "배우자 경로 질문은 주어 없이, 필요한 곳만 '코 고는 사람'. 공유받은 리포트는 '당신'"으로 고친다. 서비스 이름 줄의 탭 제목 "3분 코골이 무료진단"은 유지한다.
- `docs/architecture.md`에 경로 쿼리와 사용자 속성을 반영한다(분석 흐름이 있으면).

## 성공 기준

- 두 경로 모두 랜딩 → 질문 9개 → 리포트 → 병원 목록까지 간다. 경로별 문구가 ux-spec 표와 같다.
- 같은 답이면 두 경로의 판정 단계가 같다.
- 카드를 고를 때 `check_start`와 `respondent_role`이 GA로 가고, 증상 답은 가지 않는다. 메타 픽셀 호출은 그대로다.
- 글자 200%·폭 320px에서 랜딩 카드 두 장이 잘리거나 겹치지 않는다. 글자 16px 이상, 터치 48px 이상, 대비 7:1(`make fe-a11y`).
- `/c/*`가 사라지고, `/check`에 경로 없이 들어오면 `/`로 간다.
- `make gate` 통과.
